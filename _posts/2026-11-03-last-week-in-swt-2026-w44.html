Here is what I wrote or reviewed in SWT that got merged during the week of October 26 - November 1, 2026. Most of it is GTK4 again: drag and drop is now usable in the EGit Staging view, and GLCanvas finally works on Wayland. The screenshots show the commit before the change next to the change itself, both running on GTK4 under Wayland unless noted otherwise.

GLCanvas on Wayland and GTK4

  • GLCanvas used GLX and an X11 child window, so it failed on Wayland and called GTK3-only API on GTK4. It now uses a GtkGLArea there, and GTK3 on X11 keeps GLX. GDK only creates core profile contexts, so code using the fixed function pipeline needs shaders (or GDK_GL=legacy on GTK3) (PR 3779)
  • Snippet195 and Snippet341 now draw with vertex buffers and shaders, so they run with both the new GLCanvas and on macOS (PR 3779)

Drag and drop on GTK4

  • Show the dragged rows of a Tree, Table or List as the drag image instead of GTK's generic icon. It is drawn at the widget's scale, so it stays sharp on HiDPI (PR 3776)
  • Keep a multi selection when you drag one of its rows. GtkTreeView selected only the pressed row on the press, so only that row was dragged (PR 3772)
  • Offer drag transfers that send no data. JFace's LocalSelectionTransfer keeps the selection in Java, so dragging from unstaged to staged changes in EGit did nothing (PR 3765)
  • Give an image from Image.gtk_new() the size of its surface, so getBounds() of the drag images is no longer 0x0 (PR 3775)

Popups and Trees on GTK4

  • Send Activate and Deactivate to ON_TOP child shells, which are GtkPopovers on GTK4. GTK hid such a popup on an outside click, but SWT never told the application, so a popup that disposes itself on Deactivate stayed alive. Now it gets the event and closes properly (PR 3766)
  • Turn off GtkTreeView's search for Trees, Tables and Lists without search (NO_SEARCH, VIRTUAL). Typing used to print Gtk-CRITICAL: gtk_css_node_insert_after: assertion 'previous_sibling == NULL || previous_sibling->parent == parent' failed (PR 3767)
  • GTK 4.8 is now the minimum, and Display warns at runtime if GTK is older (PR 3778)

Reviewed and merged contributions

  • Navigate Tree rows with Left and Right as on Windows, on GTK3 and GTK4: Right on an expanded row moves to its first child, and Left on a leaf moves to its parent (by anydoby, PR 3744)
  • Hook the real unrealize signal for Widget.UNREALIZE. It was hooked to realize, which crashed JFace dialogs with a native TabFolder on GTK 3.24.44 to 3.24.49 without ibus (by openaudible, PR 3754)
  • Skip Control.setBackground when the colour is unchanged. This saves about 42 ms per 1000 controls on GTK3 when a theme switch re-applies colours (by vogella, PR 3736)
  • Declare six WebKitGTK natives void, as the C functions are (by GreenFuze, PR 3774)
  • Drop the unused className parameter of SWT_AWT.initFrame and deprecate SWT_AWT.embeddedFrameClass for removal (by GreenFuze, PR 3719)
  • The Display asyncExec test now asserts that its runnable actually runs, on the UI thread (by vogella, PR 3745)

Build and tools

  • Install the WebKitGTK 4.1 runtime instead of webkit2gtk-driver, which is gone in Ubuntu 26.04 (PR 3764)
  • Remove the "Generating" message from the JNI generator (PR 3773)

All of this is in the current I-builds (natives v4975r20). Please give GTK4 (SWT_GTK4=1) and Wayland a try and report what breaks for you.
